# Drawer

Uma gaveta que desliza da borda da tela. Serve para ações e formulários curtos, sobretudo no celular.

<Canvas of={DrawerStories.Demo} />

O exemplo principal do shadcn troca entre uma gaveta de baixo (celular) e uma lateral (desktop) com o hook `useIsMobile`. Como as stories desta página são JSX literal, que não chama hooks, o exemplo é uma gaveta de baixo, o `swipeDirection` padrão. Os lados têm a própria seção, **Posição**.

O Drawer deste registro usa o [Drawer do Base UI](https://base-ui.com/react/components/drawer), não o vaul.

## Instalação

O Drawer usa o `@base-ui/react` e o `cn`, que já estão no pacote.

<Source language="bash" dark code="npx shadcn add drawer" />

Ele já está no pacote, mas, para reinstalar, rode o comando dentro de `packages/ui`. O CLI usa o `shadcn` local (versão fixa) e sobrescreve o arquivo com o estilo do preset: depois, reaplique as decisões anotadas no comentário do topo do componente.

O componente está no pacote `@workspace/ui`, em `packages/ui/src/components/drawer.tsx`.

No iOS Safari, o véu da gaveta é posicionado de forma absoluta e precisa de um `body` posicionado para cobrir a tela depois que a página rola. Acrescente aos estilos globais do seu app (veja os [detalhes na documentação do Base UI](https://base-ui.com/react/overview/quick-start#ios-26-safari)):

O `DrawerContent` já compõe o portal, o véu, a área de exibição e o popup do Base UI. Para controlar cada peça, o pacote também exporta `DrawerPortal`, `DrawerOverlay` e `DrawerSwipeHandle`.

## Acessibilidade

- **Nome e descrição:** o popup tem `role="dialog"` e o Base UI o liga ao `DrawerTitle` (`aria-labelledby`) e ao `DrawerDescription` (`aria-describedby`). Toda gaveta precisa de título, e ele diz a ação ou o assunto ("Escolha um horário de entrega"), não só "Atenção". Uma gaveta sem texto visível precisa de `aria-label` no `DrawerContent`.
- **Foco preso e devolvido (modal):** com a gaveta modal aberta, o foco vai para dentro dela e o Tab não sai dali, porque o resto da página fica inerte. Esc fecha, e o foco volta para o gatilho. O teste da story **Demo** confere isso (Tab oito vezes, Esc e o foco no gatilho).
- **Gatilho e fechamento:** `DrawerTrigger` e `DrawerClose` recebem o elemento pela prop `render`, como `render={<Button variant="outline" />}`, sem `div` envolvendo. Os dois são `<button>`, porque abrir e fechar são ações. Uma gaveta aninhada precisa de botões de fechar com nomes distintos ("Fechar gaveta aninhada"), para quem usa leitor de tela saber qual fecha.
- **Gesto não é o único jeito:** arrastar para fechar é um atalho para o toque. Quem usa teclado ou leitor de tela fecha com Esc ou com o `DrawerClose`, então ofereça sempre um botão de fechar visível. A alça de arrasto (`showSwipeHandle`) é decorativa e tem `aria-hidden`.
- **Não modal:** com `modal={false}`, a página de trás continua interativa e o foco não fica preso. Use `modal="trap-focus"` para prender só o foco. Combine `modal={false}` com `disablePointerDismissal` para a gaveta não fechar num clique fora; Esc e o `DrawerClose` continuam fechando.
- **Véu de fundo:** o `DrawerOverlay` escurece a página (`bg-black/30` com desfoque), a única cor com opacidade do componente. Ele não carrega texto, então não tem contraste a cumprir: quem destaca a gaveta é o fundo `popover`, com o texto `popover-foreground` (19,7:1 no claro e 16,7:1 no escuro).
- **Formulários:** os campos têm rótulo persistente (`Label` com `htmlFor`), e a descrição e o erro ficam ligados ao campo por `aria-describedby` e `aria-errormessage`.
- **Rolagem:** uma região que rola dentro da gaveta precisa ser alcançável pelo teclado. Se ela já contém controles focáveis, como os botões de opção da **Demo**, o teclado rola sozinho. Se tem só texto, dê a ela `tabIndex={0}`, `role="region"` e um nome (`aria-labelledby` com o `id` do `DrawerTitle`), e o anel `focus-visible:ring-3 focus-visible:ring-ring focus-visible:ring-inset`.
- **Movimento:** a gaveta anima por 450ms. Quem pede menos movimento no sistema (`prefers-reduced-motion`) deve ter as animações do seu app reduzidas; confira isso no seu produto.
- **Testes:** a gaveta fechada não existe para o axe. Por isso cada story tem um `play` que abre a gaveta e espera o deslize e o véu terminarem; o axe roda depois, com a gaveta aberta, no claro, no escuro e em RTL.

## Tamanhos personalizados

Uma gaveta vertical se ajusta ao conteúdo e é limitada a `calc(100dvh - 6rem)`. Uma gaveta lateral ocupa `75%` da largura da tela, ou `24rem` em telas maiores.

Para mudar a altura de uma gaveta vertical, use `h-*` e `max-h-*` no `DrawerContent`.

<Source language="tsx" dark code={`<DrawerContent className="h-[50vh]">`} />

Para mudar a largura de uma gaveta lateral, use `w-*` e `max-w-*` no `DrawerContent`.

<Source language="tsx" dark code={`<DrawerContent className="w-96">`} />

Quando o mesmo componente aparece em várias direções, restrinja a mudança a um eixo com as variantes `data-[swipe-axis=*]`.

<Source
  language="tsx"
  dark
  code={`<DrawerContent className="data-[swipe-axis=y]:max-h-[50vh] data-[swipe-axis=x]:w-96">`}
/>

Para uma região rolável, faça do contêiner de rolagem um item flex. Evite `h-full`, que não resolve dentro de uma gaveta que se ajusta ao conteúdo.

<Source
  language="tsx"
  dark
  code={`<DrawerContent>
  <DrawerHeader>...</DrawerHeader>
  <div className="flex-1 overflow-y-auto p-4">{/* Conteúdo rolável */}</div>
  <DrawerFooter>...</DrawerFooter>
</DrawerContent>`}
/>

## Posição

Use a prop `swipeDirection` para escolher o lado da gaveta. As opções são `up`, `right`, `down` e `left`.

`left` e `right` são lados físicos: a gaveta fica na borda esquerda ou direita da tela também em RTL, porque o gesto de fechar é físico. O teste da story confere a posição nos três modos.

## Não modal

Use `modal={false}` para permitir a interação com o resto da página enquanto a gaveta está aberta. Combine com `disablePointerDismissal` para impedir que um clique fora feche a gaveta. Use `modal="trap-focus"` para prender o foco dentro da gaveta sem restringir a rolagem nem o ponteiro.

<Canvas of={DrawerStories.NaoModal} />

## Pontos de ancoragem

Use `snapPoints` para ancorar a gaveta em alturas predefinidas. Números entre `0` e `1` são frações da altura da tela; números maiores que `1` são pixels; textos aceitam as unidades `px` e `rem`. Os pontos valem para gavetas verticais.

Acompanhe o ponto ativo com as props controladas `snapPoint` e `onSnapPointChange`. No ponto máximo, a gaveta recebe `data-expanded`, que você estiliza com a variante `data-expanded:`.

<Canvas of={DrawerStories.PontosDeAncoragem} />

## Responsivo

Combine `Dialog` e `Drawer` para um diálogo responsivo: um `Dialog` no desktop e um `Drawer` no celular. Esta é a única story com um componente auxiliar (`PerfilResponsivo`), porque ela precisa do hook `useIsMobile`. O teste roda numa tela larga e abre o ramo do `Dialog`.

<Canvas of={DrawerStories.Responsivo} />

<Source
  language="tsx"
  dark
  code={`import { useIsMobile } from "@workspace/ui/hooks/use-mobile"

function PerfilResponsivo() {
  const isMobile = useIsMobile()
  const [open, setOpen] = React.useState(false)
  const formulario = (
    <form className="grid items-start gap-6 p-4 md:p-0">
      <div className="grid gap-3">
        <Label htmlFor="email">E-mail</Label>
        <Input type="email" id="email" defaultValue="maria@exemplo.com.br" />
      </div>
      <div className="grid gap-3">
        <Label htmlFor="usuario">Usuário</Label>
        <Input id="usuario" defaultValue="@mariasouza" />
      </div>
      <Button type="submit">Salvar alterações</Button>
    </form>
  )

  if (!isMobile) {
    return (
      <Dialog open={open} onOpenChange={setOpen}>
        <DialogTrigger render={<Button variant="outline" />}>
          Editar perfil
        </DialogTrigger>
        <DialogContent className="sm:max-w-[425px]">
          <DialogHeader>
            <DialogTitle>Editar perfil</DialogTitle>
            <DialogDescription>
              Faça as alterações no seu perfil aqui.
            </DialogDescription>
          </DialogHeader>
          {formulario}
        </DialogContent>
      </Dialog>
    )
  }

  return (
    <Drawer open={open} onOpenChange={setOpen}>
      <DrawerTrigger render={<Button variant="outline" />}>
        Editar perfil
      </DrawerTrigger>
      <DrawerContent>
        <DrawerHeader>
          <DrawerTitle>Editar perfil</DrawerTitle>
          <DrawerDescription>
            Faça as alterações no seu perfil aqui.
          </DrawerDescription>
        </DrawerHeader>
        {formulario}
      </DrawerContent>
    </Drawer>
  )
}`}
/>

## Referência da API

O `Drawer` é construído sobre o [Drawer do Base UI](https://base-ui.com/react/components/drawer#api-reference): `DrawerTrigger`, `DrawerPortal`, `DrawerClose`, `DrawerOverlay`, `DrawerTitle` e `DrawerDescription` repassam as props do Base UI (por exemplo `render` no gatilho e no `DrawerClose`). O `DrawerContent` aceita as props do Popup do Base UI (por exemplo `initialFocus`).
